This plan touches =src/client.rs=, =src/visuals.rs=, =src/game.rs=, =src/map.rs=
and a new =src/ui/= tree, building the surface the player sees on top of the
state replicated by [[file:09-networking.org][09-networking.org]]. It adds no simulation: the client
stays a dumb renderer (=decide-authority=), so every figure shown is authoritative
state or the local build ghost, and every action is an intent, never a mutation.

** TODO [#A] Define the UI data contract and add a LocalPlayer marker :@ui:
   :PROPERTIES:
   :ID:         ui-001
   :EFFORT:     1w
   :END:
   The client infers "my" state because =update_hud= calls =me.single()= and the
   only =PlayerView= it happens to hold is its own; that breaks in host mode
   (=D3=) and there is no notion of ownership at all (=D30=). Write down exactly
   what the client learns from replication (=PlayerView=, =MatchView=,
   =TowerVis=, =CreepVis=, =CreepHp=) versus what it derives from shared balance

   selection can say "mine". Every other task in this file assumes this contract.

   | HUD field          | Source                                  |
   |--------------------+-----------------------------------------|
   | wave, phase        | =MatchView= (replicated)                |
   | live / overrun cap | =MatchView= (replicated)                |
   | gold, kills        | =PlayerView= (replicated, mine only)    |
   | tower stats/cost   | shared balance data (=found-004=)       |
   | placement legality | shared buildability predicate           |

   - Files: =src/game.rs=, =src/client.rs=, =src/protocol.rs=, a new =src/ui/mod.rs=
   - Acceptance:
     - [ ] A =LocalPlayer= identity is established on connect and is never inferred from how many =PlayerView= entities happen to be held (=D30=).
     - [ ] A field-by-field table records, for each HUD value, whether it is replicated or derived from shared balance data.
     - [ ] The HUD renders correctly both for a host holding every =PlayerView= and for a remote client holding only its own (=D3=).
     - [ ] No HUD field is produced by a client-side simulation step.
     - [ ] =update_hud='s =me.single()= call is removed or made total, so host mode can never silently render nothing.

* Non-goals
  - No client-side simulation, prediction or authority: the client renders and
    sends intents only (=decide-authority=). Interpolation is owned by
    [[file:09-networking.org][09-networking.org]].
  - No gameplay rules, costs or wave numbers: those live in
    [[file:04-waves.org][04-waves.org]], [[file:05-towers.org][05-towers.org]] and
    [[file:06-economy.org][06-economy.org]].
  - No protocol or message definitions: those are [[file:09-networking.org][09-networking.org]]
    =net-001= and =net-017=.
  - No art production: this file consumes the assets from
    [[file:11-content.org][11-content.org]] and only decides where they appear.
  - No new TODO keywords; only the six in the header are used.

* Open questions
  - *Default zoom.* The original documents 2500 units. Recommended default:
    2500 (tune), clamped to a range derived from the loaded map bounds
    (=map-007=), recorded in the config layer ([[file:00-foundation.org][00-foundation.org]] =found-001=).
  - *Multiboard scope.* Show every player's row or only the local board?
    Recommended default: all players, with the =LocalPlayer= row highlighted.
  - *Message log depth.* Recommended default: 8 visible lines with a 200-line
    scrollback (tune), set by =-gmd=.
  - *Health-bar visibility.* Recommended default: always on for boss and hero,
    otherwise on selection/hover and below a health threshold (tune).
  - *Quest panel key.* Recommended default: F9 to match the original, remappable
    per ui-017.
