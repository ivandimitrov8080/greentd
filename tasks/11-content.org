This plan touches a new =assets/= tree, =src/ui/visuals.rs=, =src/ui/theme.rs=, a
new =src/audio.rs= and the asset manifest/check tooling. The visual layer today
is entirely procedural — one ground sprite over the board's zones, one bar per
lane segment, creeps darkened by health fraction in =track_creeps=, towers scaled
by =level.min(6)= — with no =assets/= directory, no animation, no VFX and no
audio. It runs after the sim has named every unit and tower.

* Non-goals
  - Not a Warcraft III asset clone: no Blizzard art, names, sounds or textures
    may be used or imitated closely (=content-001=).
  - No gameplay or balance numbers: creep and tower stats live in
    [[file:04-waves.org][04-waves.org]] and [[file:05-towers.org][05-towers.org]]; this file only names art
    for them.
  - No UI layout decisions: where a panel sits is [[file:10-ui.org][10-ui.org]]; this file
    supplies assets and the palette.
  - No voice acting, licensed music or third-party audio that is not
    licence-clear.
  - No new TODO keywords; only the six in the header are used.

* Open questions
  - *2D sprites or 3D models?* Recommended default: 2D sprites for the first
    pass, because the sim is top-down and the original's units read as billboards;
    revisit only if a specific effect demands 3D.
  - *Hot reload in release builds?* Recommended default: dev-only, compiled out of
    release to keep the shipped binary's asset loading deterministic.
  - *One tileset per map or a shared base?* Recommended default: a shared base
    tileset plus per-map decoration, so a new map is data, not a new art set.
  - *How to make the icon set?* Recommended default: generate icons from the model
    keys with tier decoration, so a new tier never needs a hand-drawn icon.
  - *Air/armour slot icon.* The original substitutes a vulture icon for the armour
    slot on air waves. Recommended default: a distinct neutral air glyph, not a
    copy of any original icon, defined in =content-001=.
