This plan touches a new =tests/= and =benches/= tree, =src/sim.rs= (a state hash
and =#[cfg(test)]= helpers), =src/server.rs=, =src/protocol.rs=, new =src/bot.rs=
and =src/replay.rs=, and the CI pipeline from [[file:00-foundation.org][00-foundation.org]]
=found-007=. There are tests as of =test-001= (=tests/sim_smoke.rs=,
=tests/balance.rs=), which closed D17; the rest of this file is what grows
around them. =Sim= is a testable =step(dt) -> Vec<SimEvent>= state machine over
HashMaps, and the harness in =test-001= is the headless one every task here
extends.

* Tasks

** IN-PROGRESS [#A] Build the headless simulation test harness :@test:
   :PROPERTIES:
   :ID:         test-001
   :EFFORT:     1d
   :END:
   The minimum everything else needs: a way to construct a =Sim= with a fixed
   seed, run N =step= calls with no window and no sockets, and assert on the
   resulting state and on the returned =SimEvent=s. =Sim::new()= already exists
   and =step= already returns events, so this is a harness rather than a
   refactor; it fixes =D17= and is the foundation of the whole file.

   - Files: =tests/sim.rs= (or a =#[cfg(test)] mod tests= in =src/sim.rs=), =Cargo.toml= dev-dependencies
   - Acceptance:
     - [x] A test builds =Sim::new()=, runs N =step= calls and asserts on state.
     - [x] The suite runs under =cargo test= with no window and no OS sockets opened: no test builds an =App=, so both are impossible by construction. 19 tests, 0 failures.
     - [x] A helper sets up players, towers and waves so later tests need no boilerplate.
     - [ ] =SimEvent=s can be collected and asserted per tick, and a fixed seed is threaded in.

   Three of four boxes are done; see =audit-010= in
   [[file:01-current-code-audit.org][01-current-code-audit.org]], which is the
   same harness and carries the detail. Events are collected per tick, and
   =Harness::with_players=/:with_balance= remove the boilerplate.

   The fourth box was *held* on a precondition that has since been met, so the
   sentence that held it is corrected rather than repeated. It used to read "=Sim=
   has no RNG concept yet, so a fixed seed cannot be threaded in until
   =found-009= adds the seeded RNG the sim owns. Do not tick this box before
   then." =found-009= is =DONE=, and both halves of the box now hold in
   =tests/sim_smoke.rs=: events are asserted per tick through =Harness::step=, and
   the =seeded_balance(seed)= helper threads a fixed seed in -- which is exactly
   what =the_same_seed_replays_and_a_different_seed_does=,
   =a_creep_spawns_inside_its_own_slot= and =the_match_seed_comes_from_the_tables=
   exercise.

   *The box and the state are left alone anyway, and that is a deliberate
   choice.* Two readings are defensible and they disagree, so the decision is
   recorded here rather than taken silently:

   - The literal reading is that the precondition named in this paragraph is
     satisfied, so the box should be ticked.
   - The README's *Progress against M0* gives a second, independent reason for
     the task being open: it is the harness every sibling test extends, so it is
     a live artefact rather than a finished one, and a task is not closed by
     having no boxes left.

   The second reading is the one this file acts on, which is why =test-001= stays
   =IN-PROGRESS= with a true box unticked. Whoever owns the milestone should
   settle it, and the honest form of settling it is one of: tick the box and
   leave the task open as a standing harness, or split the standing part out
   (a =test-000= "keep the harness alive") and close this one.

** TODO [#A] Determinism test: same seed and command log, same state hash :@test:
   :PROPERTIES:
   :ID:         test-002
   :EFFORT:     1w
   :BLOCKED-BY: test-001, sim-012
   :END:
   The same seed and the same input sequence must produce a byte-identical state
   after a long run (10000 ticks). This is expected to fail today, because =Sim=
   iterates =HashMap=s for creeps, towers and players while applying damage, and
   float results depend on application order. Note the dependency on =sim-012=,
   which is where the deterministic iteration and seeding this relies on is
   established; the failure before it is done is the point of the test.

   - Files: =src/sim.rs= (a state-hash function), =tests/determinism.rs=
   - Acceptance:
     - [ ] A state hash covers creeps, towers, players, =wave= and =over=.
     - [ ] Two runs with the same seed and command log produce the same hash over 10000 ticks.
     - [ ] Container iteration order is pinned (ordered or sorted keys) as provided by =sim-012=.
     - [ ] The 10000-tick run completes inside the CI time budget.

** TODO [#B] Property tests for the simulation's invariants :@test:
   :PROPERTIES:
   :ID:         test-009
   :EFFORT:     1w
   :BLOCKED-BY: test-001, test-003
   :END:
   Generate long random command sequences and assert the invariants that must
   hold no matter what the players do. This is the adversarial twin of the
   golden tests: it asserts the things that are cheap to break and expensive to
   notice — NaN positions, negative gold, an uncapped live-creep count, a build
   on the path — and it fuzzes the message decoder alongside them.

   - Files: =tests/props.rs=, =fuzz/= (=cargo-fuzz=), =Cargo.toml= (=proptest= or =quickcheck=)
   - Acceptance:
     - [ ] Generated command sequences never drive gold below zero.
     - [ ] No creep position or health is ever NaN or infinite.
     - [ ] A creep at or below zero health is always reaped, and the creep cap is never exceeded without ending the match.
     - [ ] A build on the path is never accepted, and the decoder never panics on arbitrary bytes.

* Open questions
  - *Property-test crate?* Recommended default: =proptest=, for its shrinking
    and its strategies.
  - *Benchmark harness?* Recommended default: =criterion= with a wall-clock
    budget, so a regression is a percentage, not a single noisy number.
  - *Where do golden files live?* Recommended default: =tests/golden/=, committed,
    regenerated only by an explicit script so an accidental update is visible.
  - *Quarantine mechanism?* Recommended default: a quarantine target gated behind
    =#[ignore]= plus a tracked issue, run on a nightly schedule.
  - *Target scale for test-012.* Recommended default: 1000 creeps and 300 towers
    (tune), aligned with the caps stated in [[file:13-release.org][13-release.org]] =release-012=.
