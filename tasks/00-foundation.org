* Headless operation and configuration

** DONE [#A] Run the server headless with no window and no VisualsPlugin              :@found:
   :PROPERTIES:
   :ID:         found-001
   :EFFORT:     1d
   :END:

   =src/main.rs= adds =VisualsPlugin= in the =server= arm, so a "dedicated" server
   opens a window, creates a camera and spawns 768 =MapTile= sprites in
   =setup_camera_and_map=. That is D15: a headless box cannot run a match at all,
   and CI (found-007) cannot start one. Split the app builder so a server build
   adds no window or GPU plugins, and only a rendering peer adds =VisualsPlugin=.

   - Files: =src/main.rs=, =src/visuals.rs=, =src/server.rs=
   - Acceptance:
     - [x] The =server= arm adds no =VisualsPlugin=, requests no primary window, and creates no camera or =MapTile= entity.
     - [x] =cargo run -- server= reaches the listening state with =DISPLAY= unset and no GPU, without panicking.
     - [x] =host= and =client= modes still render exactly as they do today.
     - [x] =src/main.rs= no longer builds a =WindowPlugin= primary window titled ="Green TD - server"= in server mode.

   Done. =engine_plugins= picks the plugin group from the mode: a mode with a
   client half gets =DefaultPlugins= and the window it names, a dedicated server
   gets =MinimalPlugins= + =StatesPlugin= (lightyear's state machines need it) and
   a =ScheduleRunnerPlugin::run_loop(tick)= that wakes once per sim tick instead
   of spinning, so a server's frame and the sim's tick are one clock.
   =VisualsPlugin= is added only when =Mode::runs_client()=. Verified by running
   =cargo run -- server= with =DISPLAY=, =WAYLAND_DISPLAY= and =XDG_RUNTIME_DIR=
   all unset: it binds, prints =greentd::net: listening on ...= and runs waves.

   Two things the verification turned up, both fixed and both worth knowing:

   1. *Host mode did not run at all.* =Config= carried one bind address and both
      halves of a host used it, so the default =cargo run= died with =Address
      already in use (os error 98)= before it rendered a frame. The server half
      now binds =Config::server_bind_addr=, which is =server_addr= for a host --
      the address its own client dials -- and =bind_addr= for a dedicated server.
      That also makes =--server <lan-ip>:5000= the way to host for the LAN. Two
      tests, =the_mode_decides_which_socket_is_bound_by_default= and
      =a_host_serves_where_its_own_client_dials=, seal it.
   2. A readiness line, =greentd::net: listening on <addr> (<mode>)=, is logged
      when the server reaches =Started=. =found-007='s smoke job is what waits
      for it.

   Deliberately not here: a *graceful* shutdown and the deterministic tick
   guarantee. Both belong to =net-007=, which is BLOCKED-BY this task and remains
   TODO. A host is still two real sockets rather than lightyear's in-process
   host-client pair, which lightyear flags with a one-off =invalid Lightyear
   networking topology= error; =net-006= is the task that removes it.

* Observability

** DONE [#B] Structure logs on stable targets and write a per-match log file          :@found:
   :PROPERTIES:
   :ID:         found-003
   :EFFORT:     1d
   :END:

   Bare =info!/warn!/debug!= through =server.rs=, =client.rs= and =sim.rs= have no
   stable target and no policy, so =RUST_LOG= cannot isolate a subsystem and a
   post-mortem has nothing durable to read. Keep Bevy's =LogPlugin= (it already
   bridges =tracing=) and define the levels, then add a per-match file so a desync
   can be diagnosed after the fact.

   - Files: =src/main.rs=, =src/server.rs=, =src/client.rs=, =src/sim.rs=, =Cargo.toml=
   - Acceptance:
     - [x] Logs use stable targets (=greentd::net=, =greentd::sim=, =greentd::replication=, =greentd::commands=), and =RUST_LOG= can enable or silence any one without a rebuild.
     - [x] A one-page level policy is written down: what belongs at =error=, =warn=, =info=, =debug= and =trace=.
     - [x] A match writes a per-match log file whose name carries the start time and whose path is configurable (found-002).
     - [x] A rejected client command logs at =debug= with the peer key and the =Reject= reason, never at =info=.
     - [x] The commented-out =log= dependency block in =Cargo.toml= is removed with a one-line rationale.

   Done. =src/logging.rs= is the module: it names the four targets, states the
   level policy as a table with the rule behind it ("a player never sees a log
   line, so nothing a player needs belongs above =info=, and nothing an operator
   needs rarely belongs below =debug="), and supplies the layer that writes the
   file. Every =info!/warn!/debug!/trace!= in the crate now names one of the
   constants; a line with no target is a line nobody can silence.

   The file goes to =<log-dir>/greentd-<YYYYMMDD>-<HHMMSS>.log=, in UTC, from the
   new =log-dir= key (default =logs=, empty turns it off). =LogPlugin::custom_layer=
   is a bare =fn=, so the layer reads =Config= out of the world rather than
   capturing it -- =main= has already inserted it, which is why the ordering there
   matters. The subscriber does not exist at the moment the layer is built, so the
   one line announcing the file goes to stderr by hand. Verified:

   #+BEGIN_EXAMPLE
   $ RUST_LOG=warn,greentd::sim=info ./greentd server
   greentd: logging this match to logs/greentd-20260911-194955.log
   2026-09-11T19:49:58Z  INFO greentd::sim: wave 1 started (4 creeps)
   #+END_EXAMPLE

   One subsystem on, everything else off, no rebuild -- and the =greentd::net=
   "listening on ..." line that =plain info= prints is correctly absent.

   Two things worth recording:

   1. The timestamp is hand-rolled (Howard Hinnant's =civil_from_days=, fifteen
      lines) rather than pulling in =time= or =chrono=, for the same reason the
      balance hash and the sim's RNG are: a date library is a large dependency for
      one file name. =the_epoch_is_the_epoch= and
      =a_known_instant_reads_back_as_itself= pin it, including a leap day, which is
      where a hand-rolled calendar breaks.
   2. This is the only wall clock in the crate. A log file has to be named after
      the moment the process started, and that is a wall-clock question; the
      *simulation* may not read one at all (=found-009=), which is why the seed
      lives in the balance tables.

   =greentd::replication= is the one target that had no lines to re-target, so it
   gained three: which view a peer is sent and how (`broadcasting` or
   `addressing` -- the line that would have made D3 obvious months ago), the match
   state entity, and a =trace= per creep and per tower mirror. If it is ever silent,
   replication is not happening.

   Owed elsewhere: =cargo clippy -- -D warnings= is =found-007='s gate, and there
   are 16 warnings standing in its way (13 of them =neg_cmp_op_on_partial_ord= on
   the deliberate =!(x > 0.0)= NaN guards in =data/balance.rs=). That needs a
   decision -- rewrite the guards or =#[expect]= the lint with a reason -- and it
   is not this task's to make.

   The *reason* each piece went where it did is the interesting part, and it is
   written up in =main.rs= as three rules: =sim/= imports nothing from =net/= or
   =ui/= (it has to be replayable from a seed with no socket in scope), =ui/=
   never writes authoritative state, and any number a player can feel is a field
   in =assets/balance/*.ron=. Two placements are worth calling out because they
   are the ones that could have gone either way:

   1. =Reject= went to =data/reject.rs=, *not* to =net/messages.rs= with the two

      carried on the wire; it does not belong to the wire.

      stays in =net/protocol.rs= is the *act* of registering them.

   documented as the contract it always was: wave bookkeeping, then movement,
   then fire, then the bills, then the lose condition. Nothing changed
   behaviourally -- all 60 tests passed unchanged across the move, and =host=,
   =server= and =client= were each run afterwards.

   Note on the rest of the plan: later files still name the pre-split paths

** DONE [#A] Seed a deterministic RNG owned by the sim                            :@sim:
   :PROPERTIES:
   :ID:         found-009
   :EFFORT:     1d
   :END:

   Tests and replays are reproducible only if randomness is seeded and owned by the
   match, but =src/sim.rs= has no RNG concept today. Chaos difficulty randomises
   each wave's health and the classic hazards (=rand::thread_rng()=, a wall-clock
   seed) would make that, and any future roll, impossible to reproduce. Add a
   seeded =Rng= the sim owns.

   - Files: =src/sim.rs=, =src/game.rs=, =assets/balance/*.ron=
   - Acceptance:
     - [x] =Sim= owns a seeded RNG whose seed is a match setting, not a wall-clock call.
     - [x] No =rand::thread_rng()=, =rand::random()= or =Instant::now()=-derived seed is reachable from =Sim::step=.
     - [x] Two =Sim= instances built with the same seed and fed the same intents produce identical state after N ticks.
     - [x] A test seals this in: same seed gives identical output; a different seed changes at least one observable.

   Done. =sim::Rng= is SplitMix64 -- eight lines, no dependency, and identical on
   every platform, which is the whole point -- and =Sim= owns one, built in
   =Sim::new= from =match_rules.seed=. =match.ron= carries =seed: 0= and
   =waves.ron= carries =spawn_jitter=, the fraction of a slot a creep may be
   displaced from the center of it.

   The generator's consumer today is that jitter: a wave is still spread evenly
   around the loop, but no longer as a rigid comb. The jitter is validated to be
   below half a slot, so it can never reorder a wave and never touches gameplay --
   and it is the reason a different seed is observable at all, which is what
   =the_same_seed_replays_and_a_different_seed_does_not=,
   =a_creep_spawns_inside_its_own_slot= and
   =each_wave_draws_further_along_the_generator= pin down. The last of those
   matters most: it proves the generator is a stream, not a constant dressed up
   as a seed.

   =waves-002= (chaos) and =econ-00x= (gambling) are the intended real consumers.
   When =waves-001= moves wave spawning to a single spawn point the jitter may go
   with it; the seed stays regardless, because sim-012 and every replay need it.

   Two deliberate deviations from the file list above: =src/game.rs= is untouched
   -- the seed is *not* replicated, because a client does not simulate and has no
   use for it -- and =src/balance.rs= is touched, because the seed and the jitter
   are table fields and the loader has to carry them. =BalanceData::hash= zeroes
   the seed before hashing, so the protocol version stays a property of the
   *rules*: two peers in two different matches on the same tables are not in
   disagreement.

     knows which is which: =Net::views= is keyed by =PlayerKey=, which for a raw
     connection is the peer's socket address. =mark_host_view= reads that key off
     the one =RawClient= in the world -- whose =LocalId= is the very =PeerId::Raw=
     the server derived the key from -- and marks the matching view. No address
     arithmetic, no guessing, and it survives =--bind=.

   =MatchView= gained a =players= field for box three; the HUD reads the lobby
   size from the match instead of counting views, which in host mode is every
   view in the match. Both figures are the same =Sim::players_connected()= the
   wave size is built from, so they cannot disagree.

   Verified by running all three modes: =cargo run= (host) and
   =cargo run -- client= against =cargo run -- server= both report =players 1=,
   =gold 300=, =kills 0=, and the host's figure is the authoritative one.

   One thing found on the way and *not* fixed here: a host's client half
   reproduces its own copy of every replicated entity, so the world holds two of
   each -- two =MatchView=s, two sprites per creep. =update_hud= now reads the
   authoritative one (the one without lightyear's =Remote= marker) and falls back
   to the received copy when there is only that, so the HUD is right either way,
   but the duplication itself is =net-006='s: it is the same defect as D3's
   =NetworkTarget::All=, and it wants the local client to read the server's state
   rather than to be sent a copy of it.

   =src/protocol.rs= needed no change: =LocalPlayer= is not replicated, and
   =MatchView= was already registered.

** DONE [#A] Stand up the CI skeleton with a headless smoke test                      :@found:test:

   There is no CI. A pipeline needs a server that runs without a window, which is
   why it depends on =found-001=, and it should validate the balance assets, which
   is why it depends on =found-004=. It is also what keeps D17 fixed once the
   harness in =audit-010= lands.

   - Files: =.github/workflows/ci.yml= (new), =rust-toolchain.toml= (new)
   - Acceptance:
     - [x] CI runs =cargo fmt --check=, =cargo clippy -- -D warnings=, =cargo test= and =cargo build --release=.
     - [x] A smoke job boots the headless server, steps the sim N times, asserts the readiness line appears, and exits cleanly on SIGTERM.
     - [x] CI fails the build on a balance validation error and prints the offending field path.
     - [x] The pipeline is green on a commit that only touches documentation.

   Done, as three jobs in =.github/workflows/ci.yml= plus the toolchain pin and
   two scripts. The jobs are split by what they need rather than by what they
   check:

   | Job       | What it is for |
   |-----------+----------------|
   | =check=   | =fmt --all -- --check=, =clippy --all-targets -- -D warnings=, =cargo test=. No build artefacts are reused, so this is the fastest feedback. |
   | =smoke=   | =cargo build=, then =ci/smoke-server.sh= and =ci/check-balance-refusal.sh=. |
   | =release= | =cargo build --release=, on its own cache key. A debug build does not exercise =lto = "thin"= or =codegen-units = 1=. |

   Four decisions worth recording:

   1. *The 16 standing clippy warnings had to go first.* =-D warnings= would have
      failed on the first run. Thirteen were =neg_cmp_op_on_partial_ord= on the
      deliberate =!(x > 0.0)= NaN guards in =data/balance.rs= and one in
      =sim/rng.rs=; the lints were right, the guards were right, and the spelling
      was wrong. =above()=, =at_least()= and =at_most()= in =data/balance.rs= now
      say on the tin what =!(x > 0.0)= made the reader work out, and =rng.rs= uses
      =partial_cmp= directly with the reason in a comment. The remaining three were
      cosmetic: a collapsed =if= and two query type aliases in =ui/visuals.rs=.
   2. *The smoke test is a script, not inline YAML.* =ci/smoke-server.sh= is
      runnable by hand, which is the only way to debug a CI-only failure. It takes
      =GREENTD_BIN=, =GREENTD_SMOKE_PORT= and three timeouts from the environment,
      so the same script serves the job and a developer.
   3. *No =paths-ignore= for documentation.* A docs-only commit -- this file
      included -- runs the pipeline and passes, because the code did not change.
      Skipping it would leave a required check permanently =Expected=, which is a
      worse failure mode than spending the minutes.
   4. *=rust-toolchain.toml= pins =1.97.1=, and the pipeline prints =rustc
      --version=.* The pin is what the GitHub runner honours; the Nix devshell
      ignores it and takes =rustc= from nixpkgs, which is the same version today.
      The print is there so a drift shows up as a line in the log rather than as a
      mystery. See =found-008=.

   Measured, not assumed. Locally, all three jobs' commands:

   #+BEGIN_EXAMPLE
   $ cargo fmt --all -- --check && cargo clippy --all-targets -- -D warnings && cargo test
   ... 64 tests, 0 failures
   $ ./ci/smoke-server.sh
   smoke: starting ./target/debug/greentd server --bind 127.0.0.1:5199 (no display)
   smoke: listening
   smoke: the sim stepped (wave 1)
   smoke: sending SIGTERM
   smoke: OK (bound 127.0.0.1:5199, stepped, exited 143)
   $ ci/check-balance-refusal.sh
   balance: OK (refused with exit 2, named waves.scaling.hp_base)
   #+END_EXAMPLE

   What the smoke script does and does not prove. It *does* prove the server starts
   with =DISPLAY=, =WAYLAND_DISPLAY= and =XDG_RUNTIME_DIR= unset, reaches the
   readiness line, steps a real wave (~90 fixed ticks, so the tick and the wall
   clock are still one clock) and dies on SIGTERM. It *cannot* prove "no GPU",
   because it cannot take the GPU away from the child; it makes the display half
   of D15's claim and says so rather than implying both.

   Two things the script had to get right, both found by running it:

   1. *tracing colours its output even when stdout is not a terminal,* so
      =grep -F "greentd::net: listening"= matched nothing while the line was
      plainly there -- the escapes sit between the target and the colon. The
      script strips ANSI before matching (=NO_COLOR= is set on the child too, for
      a readable log, but the strip is what makes the matching correct rather than
      merely conventional).
   2. *A graceful shutdown is not asserted*, because there isn't one yet: the
      process takes the default SIGTERM action and exits 143, which is the
      assertion (0 or 143). Draining the links and flushing state first is
      =net-007='s.

   *Two things this task did not cost, and should have.* Verifying the pipeline
   meant running the binary by hand, and doing that turned up two defects that
   nothing in this repository could have caught, both bigger deals than the CI
   they were found under:

   1. =cargo run= -- host mode, the default -- panicked about three seconds into
      wave 1, and had been broken for a while. That is =audit-029= (D31).
   2. A *remote* client received no notices at all: no wave, no refusal, no game
      over. That is =audit-030= (D32), and it took a server and a client running
      at the same time, with lightyear's message trace on, to see. A host run
      cannot see it, because in host mode the same code path is in process.

   The lesson is not "run things by hand"; it is narrower and more useful. This
   pipeline starts *one* process, so it can only check what one process can show,
   and the two defects above live in what happens *between* processes. A CI job
   that starts a server and a client and waits for a wave notice on the client is
   the natural next one and is not here yet; it needs the two-process harness that
   =test-008= ([[file:12-testing.org][12-testing.org]]) is for, and until it
   exists the manual run is the instrument.
