This file plans the authoritative simulation that lives in =src/sim.rs= (later
split into =src/sim/*=), the one component that decides every outcome. It fixes
the creep data model and adds the armour/damage system (=src/game.rs=,
=assets/balance/*.ron=), defines how the sim talks to the network through
=src/protocol.rs= and =src/server.rs=, and pins the win/lose conditions that
[[file:03-map.org][03-map.org]] and [[file:04-waves.org][04-waves.org]] feed. Wave *content* lives in
[[file:04-waves.org][04-waves.org]]; this file owns only the machinery that consumes it.

* The sim's public surface and the step loop

** TODO [#A] Give =Sim= a documented surface and ordered =step= phases   :@sim:
   :PROPERTIES:
   :ID:         sim-001
   :EFFORT:     1w
   :END:
   =step(dt)= currently runs spawn, move, fire, damage, reap and the overrun
   check as unnamed inline loops inside one function, so no later task can test
   a phase in isolation and the contract with =server.rs= is implicit. Fix the
   boundary first: name the phases in order and keep =Sim= free of any
   networking type (it must not import =lightyear=).

   - Files: =src/sim.rs=, =src/sim/mod.rs=, =src/server.rs=
   - Acceptance:
     - [ ] =step= is a short function calling one named method per phase, in the documented order below.
     - [ ] The order is written in a doc comment and a test asserts a creep spawned on tick N cannot be damaged on tick N.
     - [ ] =grep -rn lightyear src/sim= returns nothing, enforced by a CI check.
     - [ ] =Creep=, =Tower= and =Player= fields are written only by =step= and the documented =try_*= entry points, never from =server.rs=.

   | # | Phase     | Responsibility                                            |
   |---+-----------+-----------------------------------------------------------|
   | 1 | spawn     | wave timer, spawn points, creep construction              |
   | 2 | move      | advance =dist=, tick status effects, resolve arrival      |
   | 3 | acquire   | per-tower target selection via the target policy          |
   | 4 | fire      | create projectiles / schedule shots, spend cooldowns      |
   | 5 | damage    | resolve projectiles, apply damage and bounty              |
   | 6 | reap      | remove dead creeps, fire kill events                      |
   | 7 | leak      | creeps past the Life Zone, lives decrement                |
   | 8 | win/lose  | evaluate the active lose rule and the victory condition   |
