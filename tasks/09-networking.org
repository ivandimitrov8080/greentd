The server owns the simulation and every client is a dumb renderer of it
(=decide-authority=). This file plans protocol v2, authority and identity,
reconnection, replication and interpolation, spectators and the dedicated
server. It touches =src/protocol.rs=, =src/server.rs=, =src/client.rs=,
=src/game.rs=, =src/main.rs= and =Cargo.toml=.

* Protocol, identity and authority

** TODO [#A] Ship protocol v2 with version negotiation                      :@net:
   :PROPERTIES:
   :ID:         net-001
   :EFFORT:     1w
   :BLOCKED-BY: found-004
   :END:
   D22: peers never exchange a version, so a client built against different
   balance numbers or a different =ClientCmd= layout desyncs silently instead of
   being refused. Derive the protocol version from the balance-data hash
   ([[file:00-foundation.org][00-foundation.org]] =found-004=) plus a schema
   revision, send it in the handshake, and answer a mismatch with a readable
   reason before any game entity exists. *This is the gating task*: every audit
   fix that changes the wire format or the replicated component set is
   =BLOCKED-BY= this one (for example =audit-009=, =audit-011=, =audit-019=,
   =audit-020= and =audit-024=), so it lands first.

   - Files: =src/protocol.rs=, =src/server.rs=, =src/client.rs=, =src/game.rs=
   - Acceptance:
     - [ ] The version is =hash(balance data) ++ schema revision=, computed once and identical on both peers.
     - [ ] A client whose hash or revision differs is refused during the handshake with a message naming which part mismatched, and the server logs it (D22).
     - [ ] The refusal happens before any =Replicate= entity or =Sim= player record is created.
     - [ ] A matching client still completes the handshake and receives its =PlayerView=.
     - [ ] Every audit task that changes the wire format lists =BLOCKED-BY: net-001=.

** TODO [#A] Give players a stable identity that survives a new port        :@net:

   - Acceptance:
     - [ ] The client generates a persistent id and sends it in the handshake; the server keys the player on it, not on =remote.0=.
     - [ ] A client reconnecting from a new port with the same id maps to the same =PlayerKey= and the same =PlayerView= (D9).
     - [ ] A second connection presenting an id already in use is either rejected or takes over the session under a documented rule; it never silently creates a second player.
     - [ ] =peer_key= no longer calls =remote.0.to_bits()=, and =PlayerKey= is derived from the id.

** TODO [#A] Let a dropped client rejoin its own player                     :@net:
   :PROPERTIES:
   :ID:         net-003
   :EFFORT:     1w
   :BLOCKED-BY: net-002
   :END:

   =Player= record and its towers in the sim, but nothing can ever reattach to
   it, so a blip is a permanent loss of gold, kills, hero level and towers. With
   identity from =net-002=, a client that reconnects inside a grace window must
   resume the same player and receive a full-state resync.

   - Files: =src/server.rs=, =src/sim.rs=, =src/protocol.rs=
   - Acceptance:
     - [ ] A client that drops and reconnects inside the grace window resumes the same =PlayerKey=, keeping gold, kills, builder ("hero") level and the whole tower board.
     - [ ] The reconnecting client receives a whole-state snapshot tied to a tick, so it renders the correct wave and board with no missing or duplicated entity.
     - [ ] After the grace window the player is treated as a leaver exactly once, under the leaver split of [[file:06-economy.org][06-economy.org]] (=econ-011=), and cannot reattach afterwards.
     - [ ] The grace-window duration is a match setting, not a literal, with a documented default (tune).

** TODO [#A] Harden authority at one validation choke point                 :@net:sim:
   :PROPERTIES:
   :ID:         net-004
   :EFFORT:     1w
   :BLOCKED-BY: net-001
   :END:
   The net layer trusts the caller in the ways D1, D2, D6, D7, D8 and D25
   expose. Rather than three patches, route every =ClientCmd= through one
   validation helper: the sender may only affect its own entities; a build or
   upgrade cell must be in the sender's build region; the phase must be Running;
   the kind must be enabled and affordable; and an unregistered key is rejected
   instead of minted. The mechanical sim-side fixes are the audit tasks
   =audit-002= (D1, D2), =audit-006= (D6), =audit-007= (D7) and =audit-008= (D8),
   and the reason variants are =audit-001= (D25). The token-bucket mechanics are
   =net-005=; this task owns the shared helper and the policy.

   - Files: =src/server.rs=, =src/sim.rs=, =src/game.rs=
   - Acceptance:
     - [ ] Every accepted =ClientCmd= variant flows through one validation function, and no intent handler is reachable from the network by another path.
     - [ ] =try_upgrade= and =try_sell= reject a tower the caller does not own with =Reject::NotOwner=, and a successful sell refunds the owner (D1, D2).
     - [ ] =CallWave= has a documented cooldown and an authority policy, so one client cannot advance waves for the whole table (D6).
     - [ ] A command from an unregistered key is rejected, and =players.entry(who).or_default()= is no longer reachable from the network (D8).
     - [ ] =Reject= gains =NotOwner=, =RateLimited=, =NotEnoughFood=, =TowerDisabled= and any other variant the invariants need, each with a =Reject::text()= string (D25).

* Non-goals

  - Client-side prediction and rollback are deliberately excluded
    (=decide-authority=); only interpolation (=net-009=) is in scope.
  - Account systems and authentication beyond the session identity of
    =net-002= are not in scope.
  - Changing the map or balance-data formats is owned by
    [[file:03-map.org][03-map.org]] (=map-001=) and
    [[file:00-foundation.org][00-foundation.org]] (=found-004=).
  - Multiboard, build panel, connect screen and the message log widget are owned
    by [[file:10-ui.org][10-ui.org]] (=ui-001=, =ui-009=, =ui-016=).
  - The authority *policy* is fixed here, but the underlying sim mutators are
    owned by [[file:01-current-code-audit.org][01-current-code-audit.org]]
    (=audit-001=, =audit-002=, =audit-006=, =audit-007=, =audit-008=).

* Open questions

  - *Browser transport*: =Cargo.toml= carries a =wasm-release= profile.
    Recommended default: defer a web client; decide in
    [[file:13-release.org][13-release.org]] if pursued.
  - *Spectator slot and delay*: recommended default: spectators consume no slot
    and receive a fixed delay (tune).
  - *Matchmaking vs LAN discovery*: recommended default: LAN discovery first
    (=net-015=), a static server list later.
  - *Interpolation delay*: recommended default: about two tick intervals
    (~=66 ms=) behind the newest sample (tune).
  - *Session-id lifetime*: recommended default: per-session only, not persisted
    to disk, since there are no accounts.
