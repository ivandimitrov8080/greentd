The server owns the simulation and every client is a dumb renderer of it
(=decide-authority=). This file plans protocol v2, authority and identity,
reconnection, replication and interpolation, spectators and the dedicated
server. It touches =src/protocol.rs=, =src/server.rs=, =src/client.rs=,
=src/game.rs=, =src/main.rs= and =Cargo.toml=.

* Protocol, identity and authority

** DONE [#A] Ship protocol v2 with version negotiation                      :@net:
   :PROPERTIES:
   :ID:         net-001
   :EFFORT:     1w
   :BLOCKED-BY: found-004
   :END:
   D22: peers never exchange a version, so a client built against different
   balance numbers or a different =ClientCmd= layout desyncs silently instead of
   being refused. Derive the protocol version from the balance-data hash
   ([[file:00-foundation.org][00-foundation.org]] =found-004=) plus a schema
   revision, send it in the handshake, and answer a mismatch with a readable
   reason before any game entity exists. *This is the gating task*: every audit
   fix that changes the wire format or the replicated component set is
   =BLOCKED-BY= this one (for example =audit-009=, =audit-011=, =audit-019=,
   =audit-020= and =audit-024=), so it lands first.

   - Files: =src/protocol.rs=, =src/server.rs=, =src/client.rs=, =src/game.rs=
   - Acceptance:
     - [x] The version is =hash(balance data) ++ schema revision=, computed once and identical on both peers.
     - [x] A client whose hash or revision differs is refused during the handshake with a message naming which part mismatched, and the server logs it (D22).
     - [x] The refusal happens before any =Replicate= entity or =Sim= player record is created.
     - [x] A matching client still completes the handshake and receives its =PlayerView=.
     - [x] Every audit task that changes the wire format lists =BLOCKED-BY: net-001=.

   Done. Three pieces, one per file the task names, plus a test file.

   *The version.* =net::protocol::ProtocolVersion= is two numbers, because a
   mismatch has two causes with two different fixes and a player told only the
   first would fix the wrong thing: =schema=, the hand-kept wire revision, now
   =2= (=SCHEMA_REVISION=), and =balance_hash=, =BalanceData::hash= from
   =found-004=. =build_protocol= computes it once from the =Balance= resource
   and inserts it, so both halves of one process -- and both ends of a
   connection -- necessarily agree about what they speak.
   =disagreement(&peer)= returns =None=, or a sentence naming every part that
   differed; =tests/protocol.rs= (7 tests) drives the whole matrix and each
   refusal case, headless.

   *The handshake.* =Handshake { version }= goes up and
   =HandshakeAck::Accepted= / =Refused { reason }= comes down, as their own
   messages rather than =ClientCmd= variants: the point of the task is that a
   peer that has not been admitted cannot reach the intent path at all, and a
   variant of the intent enum would put it there. The server's
   =on_client_connected= observer is gone -- a peer that finishes the lightyear
   handshake is now only *connected*, and =handle_handshakes= is what turns a
   connected peer into a *player*. That split is what makes box three true
   rather than nearly true: no =PlayerView=, no =Replicate=, no
   =Sim::add_player= runs until the version has been checked, and until then the
   peer is absent from =Net::links=, which is the same gate =audit-008= put on
   unregistered peers. The handshake also runs before =handle_cmds= in the
   frame, so a peer that handshakes and acts in one tick is admitted before its
   command is read.

   Two things the first draft got wrong, both found by running a server and a
   client rather than by reading:

   1. *A refusal that never arrives is a disconnect with no reason.* The first
      version sent =HandshakeAck::Refused= and inserted lightyear's
      =Disconnecting= in the same tick. =Disconnecting::on_add= removes
      =Connected= at once, and =MessagePlugin::send= only serialises entities
      =With<Connected>= -- so the refusal was written into a sender that the
      send path then skipped. Measured: the client saw nothing. The drop is now
      deferred =REFUSAL_GRACE_FRAMES= frames by an =age_refusals= system that
      runs ahead of =handle_handshakes=, so the bytes go out before the link
      goes down. This is the same class of mistake as =audit-030= (D32): a
      message that exists and is never written.
   2. *A one-shot handshake can be lost, and a reliable channel does not save
      it.* lightyear's UDP server drops the payload of every packet that
      arrives while it is still *spawning* the peer for an address
      (=lightyear_udp/src/server.rs=, =LinkOfStatus::Spawning=), and the very
      first datagram is the one it spawns on. A client that stated its version
      exactly once sat at "connecting" forever -- reproduced, 3 attempts out of
      3 under load, with the server having logged the =Spawn new LinkOf= line
      and nothing else. Reliable delivery cannot recover from it, because there
      is no entity yet to acknowledge. The client therefore repeats its
      handshake every =HANDSHAKE_RETRY_SECS= (0.25 s) until the server answers,
      and the server treats a repeat as a no-op (already in =links=) or as the
      second half of a refusal it has already given (already =Refused=).
      Re-measured after the change: 6 trials out of 6 joined, and a refusal is
      still exactly one refusal, once.

** DONE [#A] Give players a stable identity that survives a new port        :@net:
   :PROPERTIES:
   :ID:         net-002
   :EFFORT:     1w
   :BLOCKED-BY: net-001
   :END:
   D9: =peer_key= is =PlayerKey(remote.0.to_bits())= - the UDP socket address -
   so a client that reconnects from a new source port silently becomes a new
   player and drops its gold, kills and towers. Issue a client-generated
   persistent id during the handshake and map it to a session, with explicit
   takeover semantics so one peer cannot impersonate another's id. The audit-side
   identity fix is =audit-009=, which is blocked on this task.

   - Files: =src/net/messages.rs=, =src/net/client.rs=, =src/net/server.rs=,
     =src/sim/mod.rs=, =src/config.rs=, =tests/identity.rs= (new)
   - Acceptance:
     - [x] The client generates a persistent id and sends it in the handshake; the server keys the player on it, not on =remote.0=.
     - [x] A client reconnecting from a new port with the same id maps to the same =PlayerKey= and the same =PlayerView= (D9).
     - [x] A second connection presenting an id already in use is either rejected or takes over the session under a documented rule; it never silently creates a second player.
     - [x] =peer_key= no longer calls =remote.0.to_bits()=, and =PlayerKey= is derived from the id.

   Done. Identity is now a type the client owns from process start and states in
   the handshake; the socket address is not consulted anywhere.

   *The identity.* =net::messages::PlayerId(u64)= is the identity, and
   =Handshake= now carries ={ version, id }= rather than a version alone (which
   is why =SCHEMA_REVISION= moves 2 to 3 -- a wire change, not a code change the
   version could ignore). =PlayerId::generate= draws from the standard library's
   OS-seeded =RandomState= rather than adding a =rand= dependency to a crate that
   hand-rolls its own RNG, and it refuses to return zero because the sim reserves
   =PlayerKey(0)= for "no player" (=Creep::last_hit_by=). The client keeps its id
   in a =LocalIdentity= resource for the life of the process, so every connection
   it makes -- including a reconnect -- states the same one. =--player-id= (and
   =GREENTD_PLAYER_ID=) pins the id, which is how a reconnect is exercised by
   hand; a run that does not pin one generates it.

   *The server.* =peer_key= is gone. =player_key(id) = PlayerKey(id.0)= is the one
   place the mapping lives, and =claim(id, conn, links)= is the pure admission
   question: =Fresh= (nobody holds it), =AlreadyHeld= (this connection is
   retransmitting its own handshake), or =Taken= (a different live connection
   holds it). A =Session(PlayerKey)= is stamped on a connection when it is
   admitted, so a later disconnect names the player without the socket address.
   =join_player= reuses the =PlayerView= an identity already owns, and the sim's
   =add_player= was already idempotent, so gold, kills and the whole tower board
   survive -- a reconnect re-enters the same player, not a fresh one.

   *The rule, and why it is takeover and not refusal.* "An identity is held by at
   most one live connection" reads better but does not survive the transport:
   **raw UDP has no drop detection.** A client killed mid-match left its link
   "connected" on the server for the whole twelve seconds the experiment ran, and
   lightyear never noticed -- =net-014= is the task that adds a timeout for
   exactly this. So refusing a reconnect while the old link is *believed* to be
   live would make box two impossible, which is the box the task is about. The
   documented rule is therefore: **the newest connection presenting an identity
   is the player.** The old connection is dropped, the new one takes the same
   =PlayerKey= and the same =PlayerView=, and the takeover is logged at =info=.
   It never creates a second player, and it is never silent. The cost is stated
   plainly: with no authentication in scope, a peer who knows another's identity
   can displace it. =net-003= is where a session token lets a returning client
   prove itself, so the takeover can be narrowed to the peer that owns the
   session.

   Two races the takeover opens, both closed here. The loser's
   =Remove<Connected>= fires *after* the winner has claimed the key, so
   =on_client_disconnected= now releases an identity only if the connection
   leaving is the one that still holds it; and =handle_cmds= likewise acts only
   for the connection that currently holds the key, so a superseded link cannot
   spend its successor's gold in the frame before it is despawned.

   Evidence, from a server and two clients on this machine
   (=RUST_LOG=info,greentd::net=debug,greentd::replication=debug=). Client A joins
   with a pinned id; client B presents the *same* id from a **new port** while A
   is still up:

   #+BEGIN_EXAMPLE
   player PlayerKey(42) joined (identity 000000000000002a, remote Raw(127.0.0.1:5101))
   addressing: private view 152v0 for PlayerKey(42) (remote Raw(127.0.0.1:5101))
   identity 000000000000002a taken over by PlayerKey(42) (remote Raw(127.0.0.1:5102)); dropping 151v0
   player PlayerKey(42) joined (identity 000000000000002a, remote Raw(127.0.0.1:5102))
   reusing private view 152v0 for PlayerKey(42)
   addressing: private view 152v0 for PlayerKey(42) (remote Raw(127.0.0.1:5102))
   #+END_EXAMPLE

   which is all four boxes at once: the key is the identity (42 = =0x2a=), the
   new port does not change it, the *same* view entity (152v0) is reused, and the
   second connection became the player rather than a second one. Client B's own
   log reads =handshake accepted= and =marked 1257v0 as its own view (gold 300)=.

   Two clients started with no pinned id were also run together: they generated
   distinct ids and became two distinct players, so generation does not collide.

   Green: =cargo fmt --check=, =cargo clippy --all-targets -- -D warnings=,
   =cargo test= (79 tests: 3 + 7 + 25 + 7 + 7 + 8 + 22), and the three modes run
   by hand (=host=, =server=, =client=).

   Owed, and deliberately not claimed:

   - The rule is tested headless (=tests/identity.rs=: 7 tests over =player_key=,
     =claim= and =PlayerId::generate=) and the live half is a transcript. The
     test that would make it scripted -- two peers in one world with a live
     =Server= -- is =test-008='s =App= harness, the same place =net-001='s refusal
     and =audit-030='s regression belong.
   - The state that survives is asserted by construction (*the same view entity,
     the idempotent =add_player=*) and by the reused view's gold reading 300, but
     not by making it *diverge*, because this machine has no input-injection tool
     (`audit-003`'s caveat, unchanged).
   - The =--player-id= flag is what made the reconnect demonstrable without a
     reconnect implementation, which is =net-003='s. When =net-003= lands, the
     client should re-state its own id from a new socket with no flag at all.

* Non-goals

  - Client-side prediction and rollback are deliberately excluded
    (=decide-authority=); only interpolation (=net-009=) is in scope.
  - Account systems and authentication beyond the session identity of
    =net-002= are not in scope.
  - Changing the map or balance-data formats is owned by
    [[file:03-map.org][03-map.org]] (=map-001=) and
    [[file:00-foundation.org][00-foundation.org]] (=found-004=).
  - Multiboard, build panel, connect screen and the message log widget are owned
    by [[file:10-ui.org][10-ui.org]] (=ui-001=, =ui-009=, =ui-016=).
  - The authority *policy* is fixed here, but the underlying sim mutators are
    owned by [[file:01-current-code-audit.org][01-current-code-audit.org]]
    (=audit-001=, =audit-002=, =audit-006=, =audit-007=, =audit-008=).

* Open questions

  - *Browser transport*: =Cargo.toml= carries a =wasm-release= profile.
    Recommended default: defer a web client; decide in
    [[file:13-release.org][13-release.org]] if pursued.
  - *Spectator slot and delay*: recommended default: spectators consume no slot
    and receive a fixed delay (tune).
  - *Matchmaking vs LAN discovery*: recommended default: LAN discovery first
    (=net-015=), a static server list later.
  - *Interpolation delay*: recommended default: about two tick intervals
    (~=66 ms=) behind the newest sample (tune).
  - *Session-id lifetime*: decided by =net-002= -- the id is per-process and not
    persisted to disk, since there are no accounts. A returned id is a *takeover*
    (the newest connection is the player); a session token that would let a
    returning client prove itself is =net-003='s.
