This file plans the tower system: the data model that replaces =TowerStats=
and the =kind: u8= / =level: u8= pair, the branching upgrade graph, the eleven
families, target filters, auras, traps, spells, research, crits and the
build/sell lifecycle.  It touches =src/game.rs=, =src/sim.rs= (the
=src/sim/combat.rs=, =src/sim/projectiles.rs= and =src/sim/aura.rs= modules
introduced by [[file:02-simulation.org][02-simulation.org]] =sim-001=),
=src/map.rs=, =src/protocol.rs=, =src/server.rs=, =src/client.rs= and
=assets/balance/towers.ron=.  Every number the original's research could not
confirm is marked =(tune)=.

* Data model and the upgrade graph

** TODO [#A] Replace =TowerStats= and the kind/level pair with a data-driven tower tree                                    :@towers:
   :PROPERTIES:
   :ID:         tower-001
   :EFFORT:     1w
   :BLOCKED-BY: found-004
   :END:
   =tower_stats(kind)= returns a flat struct ={ name, cost, range, damage,
   cooldown, splash, slow }= and =Tower= carries a =kind: u8= into it plus an
   unbounded =level: u8= (D18).  The original instead has eleven families with
   per-tier stats and an explicit upgrade relation, so a tower's identity must
   be a family id plus a tier in a loaded table.

   - Files: =assets/balance/towers.ron=, =src/game.rs=, =src/sim.rs=
   - Acceptance:
     - [ ] =TowerStats=, the =tower_stats(kind)= function and =TOWER_KIND_COUNT= no longer exist anywhere in =src/=.
     - [ ] =Tower= stores a family id and a tier, and no integer doubles as its identity.
     - [ ] A tower record declares cost, per-tier stats, upgrade edge(s), food cost, target filter, damage type, projectile key and abilities, loaded from =assets/balance/towers.ron=.
     - [ ] The loader rejects a record naming an unknown damage type, target filter or upgrade target.
     - [ ] Both peers load the same file and its hash is part of the protocol version (found-004).

** TODO [#A] Upgrade along explicit edges and branch into different towers from tier 3                                          :@towers:
   :PROPERTIES:
   :ID:         tower-002
   :EFFORT:     1w
   :BLOCKED-BY: tower-001
   :END:
   =try_upgrade= does =t.level += 1= and =Sim::upgrade_cost= is
   =base * (level + 1) / 2=, so the integer level  *is* the tower.  In the
   original several families upgrade into *different* towers from tier 3, and a
   fresh tower can be jumped straight to level 5 or 10 — none of which a counter
   can express.

   - Files: =src/sim.rs=, =src/game.rs=, =assets/balance/towers.ron=
   - Acceptance:
     - [ ] An upgrade follows an edge to a (family, tier) pair and may change the family.
     - [ ] =level += 1= no longer appears in =try_upgrade=.
     - [ ] A family may have more than one outgoing edge at a tier, so branching from tier 3 is representable.
     - [ ] A fresh level-1 tower can jump directly to level 5 or level 10 when the data provides the chain, paying the summed edge cost.
     - [ ] =try_upgrade= returns a rejection, never a panic, when no edge exists for the requested target.

* Open questions

  - Shuriken (11 vs 12) and Chaos (4 vs 5/6) tier counts differ between
    versions.  Recommended default: the PROs 18.3 counts (Shuriken 11, Chaos 5).
  - Whether Poison crits at all.  Recommended default: no crit at low tiers,
    enabled from tier 15 to match the confirmed note.
  - Whether the Aura tower unlocks at wave 15 or is always available.
    Recommended default: wave 15  =(tune)=.
  - Per-tier cost, damage, range and rate are unknown.  Recommended default: a
    smooth geometric curve seeded from the existing =src/game.rs= values (Basic
    80, Cannon 150, Frost 120), all  =(tune)=.
  - Whether a crit may apply against Divine armour.  Recommended default: only
    chaos-type crits apply against Divine.
