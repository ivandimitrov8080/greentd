and =assets/balance/*.ron=. Numbers research could not confirm are =(tune)=.

** TODO [#A] Select among the seven game modes                            :@lobby:
   :PROPERTIES:
   :ID:         lobby-004
   :EFFORT:     1w
   :BLOCKED-BY: lobby-001
   :END:
   All seven modes are mutually compatible and each adds +2 income:

   - Endless - after wave 60 the game keeps spawning creeps that gain armour and
     health every wave; with Random Waves enabled, 300 waves are generated.
   - Gold Rush - above 60% health a creep has a 10% chance when attacked to
     enter a gold rush (more health, armour and movespeed); a leak costs 5 lives
     and the killer gets 50 gold.
   - Swarm - total creeps per wave is doubled, excluding bosses.
   - Random Waves - every wave may have a different armour type, drawn from a
     pool of 301 units over 7 armour types (43 each, tune).
   - Headhunter - random bosses can spawn; killing one pays all players, and a
     leaked boss is an instant loss.
   - Speed - the spawn interval shrinks and creep movement speed is set to 400
     (tune).
   - Blitz - waves spawn on a timer instead of after the current wave is
     cleared.

   Store the active set as a =GameModes= bitset in the match settings so it can
   be tested, replicated and printed by =-gm=. The per-mode mechanics are
   owned by [[file:04-waves.org][04-waves.org]] (=waves-005= through =waves-011=);
   this task owns the set.

   - Files: =src/sim.rs=, =src/game.rs=, =src/server.rs=, =src/lobby.rs=,
     =src/protocol.rs=, =assets/balance/modes.ron=
   - Acceptance:
     - [ ] =GameModes= is a bitset with one bit per mode; all seven can be set at once with no conflict.
     - [ ] Each set bit contributes exactly +2 to each player's income, composing with the difficulty and disabled-tower terms of =econ-003=.
     - [ ] =-gm= prints the active mode names to the requesting player.
     - [ ] A mode can never be half-enabled: no mode-specific code path runs unless its bit is set, and the set is replicated identically to every peer.

** TODO [#A] Restart the match after a defeat                              :@lobby:
   :PROPERTIES:
   :ID:         lobby-010
   :EFFORT:     1w
   :BLOCKED-BY: lobby-001
   :END:
   The original's =-restart= (offered on 0 lives) begins a fresh game in the
   same lobby, and shows a 60-second timer on loss. Specify exactly what a
   restart resets: creeps, towers, gold, kills, builder ("hero") levels, the wave
   counter and the lose state - but not the chosen modes, difficulty, disabled
   towers or lose rule, which persist into the new match.

   *The mechanical half is done, in =audit-018=.* =Sim::reset()= clears the board,
   the wave clock, the creep ids and the terminal =over= flag and restores each
   player's gold, kills and wave-call cooldown; =net::server::reset_match= clears
   =Net::announced_over= in the same call. So D20 and D21 are closed, and the
   sentence that used to stand here - "a restarted match could neither run nor
   announce its next defeat" - is no longer true. What is left is the *flow*,
   which is this task: what triggers the reset (the original's timer, or red's
   command), what the phase does across it, and that the lobby's settings survive
   it. Nothing fires =ResetMatch= yet.

   One thing =audit-018= settled that this task's earlier boxes got wrong, and it
   is worth stating because the old wording asked for the opposite: the per-peer
   =PlayerView= mirrors are *not* despawned and respawned. A rematch is the same
   players on the same keys, so their views persist and their figures are
   overwritten by =sync_player_views= from the reset sim. Only the board is
   rebuilt, and even that needs no new code - =sync_creeps= and =sync_towers=
   already reap a mirror whose sim counterpart is gone. The boxes below say this
   now.

   - Files: =src/sim/mod.rs=, =src/net/server.rs=, =src/lobby.rs=, =src/ui/hud.rs=
   - Acceptance:
     - [ ] A restart resets =Sim= (=wave=, =creeps=, =towers=, per-player gold and kills, builder levels once =07-builder.org= has them) to a fresh state and returns the phase to Setup or Running.
     - [x] =Net::announced_over= is cleared so the next defeat announces again (D21) - closed by =audit-018=, which clears it in the same call as =Sim::reset()=.
     - [ ] The board is emptied of this match's creeps and towers with no orphans, and the per-peer =PlayerView= mirrors survive the reset with their figures overwritten (=audit-018=).
     - [ ] The match settings (modes, difficulty, disabled towers, lose rule) survive a restart unchanged.
     - [ ] The client HUD is cleared and the game-over text removed.
     - [ ] The restart is driven by a =ResetMatch= request rather than by a second reset path (=audit-018=).

* Open questions

  - *Exact Chaos bounty multiplier* is not recorded in the sources consulted.
    Recommended default: =200%= (tune) pending the balance pass.
  - *Setup duration*: the sources say "extended ... to 120 seconds".
    Recommended default: a data value of =120s= (tune), host-overridable.
  - *Randomisation authority*: vote or host-only. Recommended default:
    host-only, with a visible announcement (tune).
  - *Kick rules*: whether a majority can outvote the host. Recommended default:
    host-only, no vote (tune).

    shipped board's own script (=decide-default-lineage=). A Lineage A board
    (=map-013=) would select =overrun= instead.

    in [[file:09-networking.org][09-networking.org]] =net-013=.
