Waves are the pace of the match: which creeps, how many, how tough and how
fast. Today =start_wave= in =src/sim.rs= emits one anonymous creep from three
formulas and loops forever — no armour, no air, no immune wave, no boss, no
hero, no difficulty and no modes. This file specifies the creep catalogue, the
finite wave table, the wave kinds, difficulty scaling and each mode's wave
variant, as data under =assets/balance= (decide-data-driven). The sim machinery
that consumes this data lives in [[file:02-simulation.org][02-simulation.org]].

* The creep catalogue

** TODO [#A] Model the creep catalogue as data   :@waves:
   :PROPERTIES:
   :ID:         waves-001
   :EFFORT:     1w
   :END:
   Creeps are uniform today: =start_wave= takes =hp=, =speed= and =bounty= from
   the three =waves.ron= scaling curves, so a creep has no name, armour type,
   air flag or model (D11). The curves themselves are data as of =found-004= and
   there is no longer a literal here (=audit-011= closed D18), but a *curve* is
   still not a catalogue: every creep in every wave is the same unit scaled.
   Define a creep catalogue as the unit of balance and the join key between the
   wave table and the art pass.

   - Files: =assets/balance/creeps.ron=, =src/game.rs=, =src/sim.rs=
   - Acceptance:
     - [ ] Every entry declares id, model key, health, regen, armour type, movement type (ground/air), speed, bounty, leak cost, size and flags (boss/hero/immune/spell-immune).
     - [ ] The loader rejects an entry with a missing field or an unknown armour type, and rejects =air= movement with a ground-only flag.
     - [ ] The catalogue contains at least one air creep and one Divine-armour (immune) creep, both referenced by the wave table.
     - [ ] The catalogue is hashed into the protocol version so a peer with different creep data is rejected (net-001).

     - [ ] The 60-wave default and the 36-wave prefix variant are both expressible as a match-length setting using one file, and the reasoning is recorded as a =Decision= note.
     - [ ] Retuning wave 20 changes only wave 20; a test asserts waves 1-19 and 21 are unchanged.
     - [ ] The formula from =start_wave= is no longer used inside the finite range. (This box used to read "(fixes D18)"; D18 was about the *literals* and closed with =audit-011=, which moved the curve's coefficients into =waves.ron=. What is still missing here is the finite table, which is D11's and not D18's.)

    seed the table from today's curves, which as of =found-004= are the
    =waves.scaling= block in =assets/balance/waves.ron=: =hp = hp_base *
    (1 + hp_growth*(w-1))= (45, 0.28), =speed = speed_base + speed_growth*(w-1)=
    (55, 2), =bounty = bounty_base + bounty_per_wave*w= (6, 0.5), all =(tune)=.

    [[file:02-simulation.org][02-simulation.org]] =sim-002=; all =(tune)=.
  - *Which waves are boss and hero waves.* "3 boss levels" and a wave-30 Illidan
    hero are the only confirmations. Default: bosses at 10/20/30, hero at 30
    =(tune)=.
  - *Are immune waves fully immune or only resistant?* Default: full immunity
    to non-Chaos, =(tune)= (=sim-002=).
  - *Exact Speed-mode timer and movespeed.* 400 movespeed is quoted; the timer
    is not. Default: 400 and a halved interval, =(tune)=.
  - *Which tower loadout the harness should judge against.* Not decided. Default:
