This plan touches =Cargo.toml= (version and profiles), =src/main.rs= (modes and
panics), =src/protocol.rs= (version handshake), =src/server.rs= (ops), plus new
=docs/=, =LICENSE=, =CHANGELOG.md= and packaging scripts. It comes last because
it depends on the game being complete and the protocol frozen; it freezes the
protocol from [[file:09-networking.org][09-networking.org]] =net-001= and builds on =decide-authority=.

* Tasks

** TODO [#A] Version the game and report the version and protocol version :@release:
   :PROPERTIES:
   :ID:         release-001
   :EFFORT:     1d
   :BLOCKED-BY: found-004
   :END:
   There is no protocol version negotiation today, so a mismatched client desyncs
   silently instead of being rejected (=D22=), and a player who cannot join sees a
   hang rather than a reason. Version the game (not just the crate), carry a
   protocol version that incorporates the balance-data hash (=found-004=), and
   surfacing both so a rejected join can say exactly what is wrong (=net-001=).

   - Files: =Cargo.toml=, =src/protocol.rs=, =src/main.rs=, =CHANGELOG.md=
   - Acceptance:
     - [ ] The game version and the protocol version are compiled in and reported at startup and in the UI.
     - [ ] The protocol version incorporates the balance-data hash (=found-004=).
     - [ ] A version mismatch is rejected with a readable, specific message (=net-001=, =D22=).
     - [ ] A human-readable changelog exists and is updated for every release.

** TODO [#A] Define the build matrix and decide whether wasm is in scope :@release:
   :PROPERTIES:
   :ID:         release-002
   :EFFORT:     1w
   :BLOCKED-BY: release-001
   :END:
   There is nothing to download today. Define reproducible desktop builds for
   Linux, Windows and macOS, and decide whether a web/wasm target is in scope.
   =Cargo.toml= already carries a =wasm-release= profile inherited from the Bevy
   template, but =lightyear='s =udp=/=raw_connection= features do not work on
   wasm, so a web build needs a different transport or an explicit scope
   decision.

   | Target        | Transport                   | In scope for v1?      |
   |---------------+-----------------------------+-----------------------|
   | Linux desktop | =lightyear= udp             | yes                   |
   | Windows       | =lightyear= udp             | yes                   |
   | macOS         | =lightyear= udp             | yes                   |
   | Web / wasm    | needs a udp alternative     | decision (see below)  |

   - Files: CI configuration, =Cargo.toml=
   - Acceptance:
     - [ ] Reproducible builds exist for Linux, Windows and macOS from a tag.
     - [ ] The wasm target is either explicitly out of scope or paired with a named transport that replaces =udp=/=raw_connection=.
     - [ ] The wasm decision is recorded together with the =lightyear= limitation that motivates it.
     - [ ] A fresh machine can run a downloaded build with no extra setup.

** TODO [#A] Verify anti-cheat assumptions and define moderation :@release:
   :PROPERTIES:
   :ID:         release-007
   :EFFORT:     1w
   :BLOCKED-BY: net-002
   :END:
   The server is authoritative (=decide-authority=), but that only holds if
   neither the balance data nor the replicated state hands a client an advantage.
   Verify that both peers agree on the balance hash and that replicated state
   reveals nothing exploitable, then define kick, mute and ban in terms of the
   session identity — and state plainly that a ban is not durable under it (=D9=).

   - Files: =docs/moderation.md=, =src/server.rs=
   - Acceptance:
     - [ ] The balance data is verified equal on both peers by hash, so a client cannot load stronger numbers (=found-004=).
     - [ ] The replicated state is audited and its information exposure is documented; no hidden state leaks.
     - [ ] Kick and mute work, and ban is defined in terms of the session identity with its non-durability stated (=D9=).
     - [ ] An abuse-reporting path is documented and ties into release-008.

* Open questions
  - *Is wasm in scope for v1?* Recommended default: no, because
    =lightyear='s =udp=/=raw_connection= features do not work on wasm and a
    replacement transport is a project of its own; recorded in release-002.
  - *Free or paid, and where?* Recommended default: free, direct download first,
    so there is no storefront gating the update path; revisit after release-006.
  - *Are durable bans required?* Recommended default: no for v1. Bans require a
    persistent identity plus server-side storage (release-007); state the
    limitation instead of promising a ban that a reconnect defeats (=D9=).
  - *Telemetry backend?* Recommended default: none for v1. Ship opt-in local
    bundles only (release-008) and add a backend only if release-006 needs it.
  - *Default hosting path.* Recommended default: direct IP, with UDP broadcast
    LAN discovery as a convenience; a static relay is the next step up.
